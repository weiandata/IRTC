## 2. 逐条说明

### S1-01　流式引擎遇 `NA` 段错误

**根因确认**：与记录判断一致。`src/irtc_rcpp_proto_estep.cpp` 中
`int c = resp[p + j*N];` 之后直接用 `c` 索引概率数组。`NA` 在整型矩阵中是
`NA_INTEGER`（即 `INT_MIN`），于是 `probs + (j*maxK + INT_MIN)*Q` 成为野指针。

**处置**：采用记录建议的第 2 条（更彻底的方案）——让流式引擎**原生支持缺失**，
而不是在 R 层拦截报错。缺失作答现在贡献似然因子 1、不贡献期望计数，与网格法的
`resp.ind` 机制完全一致。同时按建议第 3 条加了下标合法性判断，任何越界码都按
缺失处理，不再可能以段错误收场。

**因此**：`complete.cases()` 预剔除不再必要。全部缺失作答的个案也会保留，其能力
估计落在先验均值上。

**在贵项目数据上的直接影响**：原始 85,036 例中有 2 例含缺失。1.1.1 下模型二必须
先剔除到 85,035 例；1.1.2 下两个模型都可以直接用全部 85,036 例。

### S1-02　`logLik` / `deviance` / `AIC` / `BIC` 系统性偏移

**根因确认**：与记录判断一致，且记录给出的关系式
`偏移 = n·D·log(1/h)` 经复现完全吻合。`R/irtc_mml_fast_proto.R` 中
`.mvn_density()` 返回的是多元正态**密度**，在步长 h 的网格上求和约等于
`1/h^D`，而不是 1。

**处置**：按记录建议第 1 条，把节点权重归一化为**概率质量**（`sum(weights) == 1`）。
实现上新增 `.mvn_grid_mass()`，并且在**对数尺度**上计算后再归一化——这一步是为了
S1-03：Σ 接近奇异时密度会放大到 `1/sqrt(det Σ)` 量级，直接指数化存在上溢/下溢风险。

**关键性质**：后验分布对权重的常数缩放不变，因此**题目参数、协方差、EAP 全部逐位不变**，
改变的只有报告出来的拟合量。这一点已在回归测试中锁定。

**验证**（复现记录中的 MRE，n=1000, J=9, D=3）：

| `nodes` 设定 | 1.1.1 实测偏移/n | 1.1.2 实测偏移/n |
|---|---|---|
| `seq(-6,6,len=21)` | 1.53248 | 0.00000 |
| `seq(-6,6,len=25)` | 2.07944 | 0.00000 |
| `seq(-6,6,len=31)` | 2.74887 | 0.00000 |
| `seq(-6,6,len=41)` | 3.61192 | 0.00000 |

且四种节点设定下报告出的 `loglike` 数值本身一致（−5136.815），即记录建议的
「改变 `control$nodes` 不应改变 `ic$loglike`」已成立。

按建议第 2 条新增的回归测试：同一数据同一模型下 `grid` 与 `streaming` 的
`ic$deviance` 相对差 **2e-09**。

### S1-03　潜在协方差退化（ρ→1）时输出失真

**根因确认**：与记录判断一致，与 S1-02 同源。

**处置**：分三部分。

1. **符号翻转**：由 S1-02 的质量归一化一并解决。复现记录中的验证表：

   | 真值 ρ | 估计 ρ | 1.1.1 `ic$loglike` | 1.1.2 `ic$loglike` | 独立计算 |
   |---|---|---|---|---|
   | 0.950 | 1.0000 | **+8414.38** | −6385.88 | −6385.88 |
   | 0.999 | 1.0000 | **+8508.55** | −6436.23 | −6436.23 |

   1.1.2 下报告值与独立积分计算在边界情形下也完全一致。

2. **`EAP.rel` 偏低**：这一条的根因与记录推测的不同。流式引擎用的是
   `var(EAP)/diag(Sigma)` 这一近似式，**既未加权、也未计入后验误差方差**；
   网格引擎用的是标准式 `var(EAP)/(var(EAP)+mean(SD.EAP²))` 且已加权。
   现已统一为网格引擎的定义。为此扩展了 C++ 核，使其同时返回逐人后验标准差
   （顺带补上了流式路径缺失的 `SD.EAP.Dim*` 列，见 S2-05 的附带收益）。

   验证：三维退化模型的 `EAP.rel` 现与等价单维模型**完全相同**
   （模拟数据 0.7179 vs 0.7179；贵项目真实数据 0.7223 vs 0.7223，
   与记录预期的「应为 0.7224」一致；1.1.1 下为 0.6284）。

3. **边界警告**：按建议第 2 条新增结构化警告 **W427**。措辞采纳了记录的核心
   观点——这往往是「维度分不开」这一**实质结论**，而不是数值故障：

   > `[W427] 估计得到的维度间潜在相关已达到边界（最大 |r| = 1），说明在本数据上各维度无法区分，模型已退化为更低维的结构。`
   > `建议: 建议将此视为需要降维的证据：改用更少的维度重新估计并比较。退化解下的信息准则与 EAP 信度是在已无法分辨塌陷协方差的网格上算出的，请谨慎解读。`

**未采纳**：建议第 3 条（自适应 / 旋转积分网格）。归一化后退化情形已退回到
「离散化模型的合法对数似然」，符合记录建议第 1 条的预期；自适应网格是显著的引擎
改动，收益主要在精度而非正确性，留待后续版本评估。

### S2-04　多维模型只读第 1 维斜率

**根因确认**：`R/irtc_excel.R` 中 `alpha <- B[, 2L, 1L]` 硬取第 1 维。

**处置**：新增 `irtc_item_loading()`，按 Q 矩阵读取该题**实际载荷维度**的斜率。
按记录建议，非简单结构（一题载荷多维）不再静默取第 1 维：`slope_a` 给出载荷之和，
并通过新增的 `n_loadings > 1` 明确标记该值为复合量，等值时可据此识别。
同时新增 `dimension` 列（使用 Q 矩阵列名），使 `slope_a` / `difficulty_b` 的归属
不再有歧义。

**连带修复**：`R/irtc_irt_parameterization.R` 中 `mod$item_irt` 表存在同样的
`B[, 2, 1]`。该表由**网格引擎**产出，记录未测到，但多维网格模型同样受影响。

**验证**（复现记录的 MRE）：

```

...
4      I4  1.1574       0.1430      DimB   <- 记录指出应为 1.157，1.1.1 输出 0 / NA
```

**对等值工作的提示**：用 1.1.2 之前版本从**多维**模型导出的题目参数工作簿，

### S2-06　权重未传递到 CTT / itemfit / quality

**处置**：按记录建议第 1 条实现（而非第 2 条的过渡方案）。
`irtc_ctt()`、`irtc_itemfit()`、`irtc_quality()`、`irtc_param_table()` 均新增
`weights=` 参数；`irtc()` 把已经送进 MML 的抽样权重一并下传。后三者默认取模型对象
上保存的权重，因此单独调用时也不会退回未加权口径。

覆盖范围：题目难度（p 值）、题-总相关、Cronbach's α 与 α-if-deleted、
Infit / Outfit 及其 t 统计量，以及由它们判定的质量评级。

**重要保证**：常数权重严格还原未加权结果（已由回归测试锁定），因此不使用权重的
分析完全不受影响。

**在贵项目数据上验证**（记录指出某题未加权 0.7056 / 加权 0.6281，差 7.8 个百分点）：

```
1.1.2 加权 p 值 : 0.6281 0.2459 0.5921 0.6551 0.6305 0.5019 0.7405 0.7328 0.7256 0.3080
手算加权值      : 0.6281 0.2459 0.5921 0.6551 0.6305 0.5019 0.7405 0.7328 0.7256 0.3080
未加权（1.1.1） : 0.7056 0.2952 0.6308 0.7504 0.7235 0.5865 0.8120 0.8461 0.8102 0.3401
```

**一处刻意保留的未加权口径**：`irtc_person_table()` / `irtc_results()$persons` 的
`percentile` 与 `t_score` 仍按未加权样本计算。这两列描述的是**被访者本身**而非
推及人口，且改变其定义会直接改动已发布的个体常模分。已在
`?irtc_excel` 与 `inst/llms.txt` 中明确写出该口径。如贵方希望改为加权常模，
这是一个需要贵方拍板的口径决策，可在 1.1.3 提供选项。

### S3-08　网格法内存溢出，错误信息无指引

**处置**：按记录建议，在进入网格法**之前**按 `N × nodes^D` 预估内存。
预估口径为 3 份同等大小矩阵（E 步实际持有的工作副本数），上限取
`mem.maxVSize()`。超限时抛出结构化错误 **E409**。

**复现记录中的场景**（n=85035, J=10, D=3, 21 节点，显式 `method="grid"`）：

```
[E409] 网格法预计需要约 17.6 GB 内存（85035 个样本 × 9261 个积分节点，共 3 个维度，
E 步需要约 3 份同等大小的矩阵），超过了当前会话可用的 16 GB。
  建议: 请改用 method="streaming"（题间维度的简单结构模型在该引擎下内存有界），
  或通过 control=list(nodes=seq(-6, 6, length.out=15)) 减少积分节点数。
```

`method="auto"` 的路径选择本就正确，不受影响。

### S3-09　`ic` 结构差异　/　0.1.0 → 1.1.x 迁移说明

**`ic` 结构**：已统一。流式引擎此前返回 `list`、网格法返回 `data.frame`，
写通用代码需要 `unlist(m$ic)[...]` 之类的兼容处理。现在两个引擎都返回**单行
data.frame**，`m$ic$loglike` 等写法在两条路径下行为一致。

**迁移说明**：0.1.0 → 1.0.0 的能力跃升其实已记录在 `NEWS.md` 的 1.0.0 条目
（「估计核心与 0.1.0 相同；本版新增易用层」）。核心要点是
**`irtc.mml()` / `irtc.mml.2pl()` 未变，0.1.0 的脚本无需改动**，
新增的都是其上的可选易用层。已在 1.1.2 的 NEWS 中补一条显式指路。

**文档补充**（对应记录第 5 节「行为记录」）：

- `?irtc.mml.2pl` 新增四个小节：缺失作答的处理、`ic` 可比较的范围（含 W427 提示）、
  内存守护，以及——按记录建议——**二值题下 `GPCM` 与 `2PL` 数学等价**，
  换成 GPCM 本身不带来模型变化，变化只来自 `ndim` / `Q`。
- `?irtc_itemfit` 写明残差是在 **EAP** 点估计上计算的（对应记录第 7.5 条建议），
  便于与使用 WLE 的软件对齐。
